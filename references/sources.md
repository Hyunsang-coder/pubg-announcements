# 출처 정책

## 근거는 발행물만

이 스킬의 모든 확정 표기는 **PUBG 공식 홈페이지에 발행된 공지의 KR/EN 대조**에서 나온다.
사내 문서·기획서·초안은 근거로 쓰지 않는다. 이유는 둘이다.

- 발행된 영문이 곧 플레이어가 본 표기다. 로비·상점 페이지와 어긋나지 않으려면 그것이 정본이어야 한다.
- 이 스킬은 공개 가능해야 한다. 근거가 발행물이면 출처를 그대로 적어도 문제가 없다.

## 공개 판정 한 줄

> **발행된(또는 발행 예정인) 공지 문구 = 공개 가능 / 그 문구를 확정한 내부 경로 = 비공개.**

비공개에 해당하는 것: 사내 위키 페이지 ID·스페이스 키, 팀·부서 약어, 내부 코드명, 마일스톤 번호, 협력사명, 미발표 일정.
등록할 때 근거를 적되 **"몇 개 회차를 대조했는가"까지만** 적는다 — 그건 판단의 강도를 알려주므로 남기고, 그 회차를 어디서 봤는지는 남기지 않는다.

## 근거를 어디서 가져오는가

발행 공지는 공식 홈페이지에 언어별로 올라가고, **URL 이 이런 꼴이다:**

```
https://pubg.com/<locale>/news/<id>            Store Update · 콜라보 · 대형 이벤트 공지
https://pubg.com/<locale>/events/notice/<id>   Special Drops
```

**경로가 유형에 따라 다르다.** Special Drops 는 news 가 아니라 events 아래에 있어서, news 경로로 찾으면 404 가 난다(2026-09-01 확인). `references/corpus.json` 이 회차별로 어느 경로인지를 `path` 필드에 들고 있다.

**`<id>` 가 언어와 무관하게 같은 공지를 가리킨다.** 즉 로케일 세그먼트만 갈아 끼우면 같은 회차의 KR/EN 대조본이 바로 나온다 — 이게 이 저장소의 근거 수집 방법이다.

```
https://pubg.com/ko/news/10043     KR 원문
https://pubg.com/en/news/10043     같은 공지의 발행 영문
```

- 한국어 로케일은 **`ko` 다. `kr` 은 404** (2026-08-31 확인).
- 회차 목록은 `references/corpus.json` 에 있다. 본문은 커밋하지 않는다 — 공지 전문은 PUBG 저작물이고 이 저장소는 문장 단위 대응을 담는 곳이지 원문 재배포처가 아니다. 필요할 때 받아 쓴다:

```bash
node scripts/fetch-announcement.js      # .corpus/ 에 KR/EN 본문 (gitignore)
node scripts/corpus-stats.js --audit    # 등록 정본이 몇 회차에 나오는가
node scripts/corpus-stats.js --mine     # 미등록인데 반복되는 줄 = 새 후보
```

- **몇 개 회차를 봤는가가 곧 판단의 강도**다(아래). 갈리는 표기일수록 표본을 늘린다. 눈으로 훑는 건 서너 회차까지고, 그 이상은 `--mine` 이 센다.

## 판본은 해시로 고정한다

본문을 커밋하지 않는 대신 `corpus.json` 이 회차마다 `fetched`(받은 날)와 `sha256`(추출본 해시 앞 16자)을 들고 있다.

이게 메우는 구멍은 하나다 — **근거의 재검증.** `notes` 에 "19회차 실측 15:1" 이라고 적어도, 공지가 개정되면 나중에 같은 수가 안 나온다. 그때 원인이 셋인데(내 착오 / 원문 개정 / 추출 깨짐) 해시가 있으면 둘째를 즉시 걸러낸다.

```bash
node scripts/fetch-announcement.js --verify   # 받지 않고 로컬 본문만 대조
```

`CHANGED` 는 오류가 아니다. **그 회차를 근거로 쓴 항목의 `notes` 를 다시 보라는 신호**이고, 다시 봐서 판정이 유지되면 `sha256` 을 새 값으로 갱신한다(무엇을 다시 봤는지는 `notes` 에 남긴다).

회차를 새로 추가하면 해시도 함께 기록한다 — 받은 직후의 `.corpus/<id>.<locale>.txt` 를 SHA-256 하고 앞 16자를 쓴다.

## 근거 표기 형식

`notes` 에 근거를 남길 때:

```
"24개 공지 실측 15:1 로 확정(소수형 'End of Sales Date' 는 반려)."
"4개 회차 EN 42줄 전부 이 형태."
"콤마본 3건이 전부 최근 3개월이라 최근형을 따랐다."
```

회차를 특정해야 하면 **공지 제목 + 발행 연월 + news id** 로 적는다 (`2026-09 Store Update (news/10043)`). id 는 언어와 무관하게 안정적이고 공개돼 있어서, 받는 사람이 그대로 확인할 수 있다 — 인용 단위로 이걸 쓴다.
